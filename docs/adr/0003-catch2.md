# 3. Use Catch2 as the test framework

## Context

We work in TDD, so writing and reading tests must be quick.

Alternatives considered, and why they fit worse:

- **GoogleTest:** the most widespread, and it ships a mocking library (gMock). But its assertions
  are more verbose (`EXPECT_EQ(a, b)`, `EXPECT_NEAR(a, b, eps)`), shared setup needs fixture classes,
  and we do not need mocks for a ray tracer's pure computations.
- **doctest:** syntax close to Catch2 and much faster to compile, a credible option. But it has
  less documentation and fewer recent releases, and floating-point comparison helpers are more
  limited.
- **Boost.Test:** pulls in Boost, a large dependency, for a test framework alone; its syntax and
  documentation are harder for beginners.

Our reason: a ray tracer is mostly floating-point maths (vectors, intersections, colours). Catch2
writes these tests in plain C++ (`REQUIRE(a == b)`), shows both values when a test fails, and has
matchers for approximate comparison (`WithinAbs`, `WithinRel`). `SECTION`s let several cases share
one setup without fixture classes, which keeps TDD fast for a team new to C++.

## Decision

We write tests with Catch2 v3, downloaded by CMake `FetchContent` and pinned to tag `v3.8.1`.
Tests are discovered by CTest through `catch_discover_tests`.

## Status

Accepted

## Consequences

- Tests read like plain C++ (`TEST_CASE`, `REQUIRE(a == b)`) with clear failure messages.
- The first configure needs internet access to download Catch2.
- Catch2 v3 is compiled with the project, so the first build is longer.
- Upgrades are manual (change the pinned tag), and tests are tied to Catch2's macros.
